
# Thermal Image Processing Pipeline (Landsat 9 → Lepton-like Dataset)

## Overview

This repository contains three Jupyter notebooks that together implement a complete thermal image processing pipeline based on **Landsat 9 Band 10** data.  
The goal is to generate **normalized, square, and sensor-degraded thermal PNG images** that resemble data captured by a **FLIR Lepton 3.5-like thermal camera onboard a 1U CubeSat**.

The notebooks are:

1. **Pre_Processing_Images.ipynb** (core, recommended)
2. **Post_Processing_Images.ipynb** (core, sequential)
3. **Processing_RAW_Images.ipynb** (independent, combined workflow)

The *Pre-Processing* and *Post-Processing* notebooks form the **main sequential workflow**.  
The *Processing RAW Images* notebook is **independent** and internally performs both steps on atmospherically uncorrected imagery.

---

## Notebooks and Their Roles

### 1. Pre_Processing_Images.ipynb (Core)

**Purpose:**  
Transforms Landsat 9 Band 10 images that already include temperature scaling parameters into clean, square, and normalized thermal images suitable for dataset generation.

This notebook assumes that:
- Atmospheric and radiometric corrections are already embedded in the metadata.
- Temperature can be computed directly using ST_B10 scaling coefficients.

**Main Output:**  
Auto-Gain-Controlled (AGC) thermal PNG images + metadata.

---

### 2. Post_Processing_Images.ipynb (Core)

**Purpose:**  
Applies **sensor realism degradation** to preprocessed thermal images in order to simulate a **low-resolution spaceborne thermal sensor** (e.g., FLIR Lepton 3.5).

This notebook **must be run after Pre_Processing_Images.ipynb**.

**Main Output:**  
Low-resolution thermal PNG tiles with multiple noise/degradation profiles.

---

### 3. Processing_RAW_Images.ipynb (Independent)

**Purpose:**  
Processes **raw (non-atmospherically corrected)** Landsat 9 Band 10 imagery by:
- Converting DN → Radiance → Brightness Temperature
- Performing geometric normalization
- Applying AGC
- Applying sensor degradation

This notebook **does not depend on the other two** and reproduces the full pipeline internally.

**Important:**  
Outputs represent **brightness temperature (at-sensor)**, not surface temperature.

---

## End-to-End Workflow

### Recommended (Sequential) Workflow

1. Run **Pre_Processing_Images.ipynb**
2. Run **Post_Processing_Images.ipynb**

This path is recommended when working with Landsat products that already include temperature scaling parameters.

### Alternative (Independent) Workflow

- Run **Processing_RAW_Images.ipynb** only

This path is used when working with raw images without atmospheric correction.

## Notebook Details

## Pre_Processing_Images.ipynb

### Inputs

- Landsat 9 Band 10 GeoTIFF images
- GeoJSON metadata file with scene-level properties

Required metadata fields:
- `TEMPERATURE_MULT_BAND_ST_B10`
- `TEMPERATURE_ADD_BAND_ST_B10`
- Scene identifier (LANDSAT_PRODUCT_ID)
- Acquisition date, cloud cover (used for filtering / logging)

---

### Processing Stages

#### Stage 1 — Scene Indexing and Metadata Matching

- Extracts product ID from filenames using regex
- Matches each image with its corresponding GeoJSON metadata entry
- Discards scenes with missing metadata

---

#### Stage 2 — Geometric Normalization

- Downsamples original image (mean resampling)
- Masks invalid or nodata pixels
- Detects largest valid contour
- Applies minimum-area rectangle fitting
- Rotates and warps image to obtain a **square thermal patch**
- Pads invalid regions with NaNs

This ensures all outputs have consistent geometry.

---

#### Stage 3 — Temperature Computation

Temperature is computed using linear scaling:

T = M × DN + A

Where:
- `M` = TEMPERATURE_MULT_BAND_ST_B10  
- `A` = TEMPERATURE_ADD_BAND_ST_B10  
- `DN` = Digital Number

Result is temperature in **Kelvin**.

---

#### Stage 4 — Auto Gain Control (AGC)

Three normalization modes are produced:

1. **GLOBAL**
   - Uses global 2–98 percentile range computed across the dataset

2. **AUTO**
   - Uses per-image 2–98 percentile range

3. **FIXED**
   - Uses a fixed temperature window defined in the notebook

Normalization formula:

T_norm = clip((T - T_min) / (T_max - T_min), 0, 1)

---

#### Stage 5 — Visualization and Export

- Applies a perceptually uniform colormap
- Saves:
  - PNG images (one per AGC mode)
  - Comparison plots
  - JSON metadata per image (temperature stats, scene info)

---

## Post_Processing_Images.ipynb

### Inputs

- AGC PNG outputs generated by Pre_Processing_Images.ipynb
- Images are assumed to contain black/invalid padding regions

---

### Processing Stages

#### Stage 1 — Valid Region Cropping

- Converts image to grayscale
- Thresholds near-black pixels
- Extracts bounding box of valid thermal region
- Crops image to remove padding

---

#### Stage 2 — Quadrant Splitting

- Each cropped image is split into **four sub-regions**
- Increases dataset size and spatial diversity

---

#### Stage 3 — Resolution Reduction

- Each tile is resized to **Lepton 3.5 resolution**
- Area interpolation is used to preserve energy

---

#### Stage 4 — Sensor Degradation Models

Thermal realism is introduced using the following models:

##### Additive Thermal Noise
Gaussian noise applied in normalized space:
- σ derived from temperature-equivalent noise level

##### Optical Blur
Gaussian blur simulating lens diffusion

##### Fixed Pattern Noise (FPN)
- Static per-pixel offset map
- Simulates detector non-uniformity

---

#### Stage 5 — Degradation Profiles

Three predefined profiles are applied:

- **Profile A**
  - Mild noise
  - Mild blur
  - No FPN

- **Profile B**
  - Profile A + moderate FPN

- **Profile C**
  - Stronger noise
  - Stronger blur
  - Stronger FPN

Each profile represents a different sensor quality regime.

---

## Processing_RAW_Images.ipynb (Independent)

### Key Differences

- Uses raw radiometric calibration
- Computes **brightness temperature** instead of surface temperature

---

### Radiometric Conversion

**DN to Radiance:**

L = M_L × DN + A_L

**Radiance to Brightness Temperature:**

BT = K2 / ln((K1 / L) + 1)

Where:
- `K1`, `K2` are Planck constants from metadata

---

### Workflow Summary

This notebook internally performs:
1. Metadata indexing
2. Radiometric conversion
3. Geometric normalization
4. AGC normalization
5. Sensor degradation

It produces outputs comparable to running Pre-Processing + Post-Processing sequentially.

## Notes and Assumptions

- Percentile-based AGC reduces sensitivity to outliers
- Random sampling is used for global statistics
- Brightness temperature ≠ surface temperature
- Outputs are designed for **machine learning and simulation**, not scientific temperature retrieval

---

## Intended Use

- Thermal ML dataset generation
- CubeSat payload simulation
- Robustness testing of thermal perception algorithms
